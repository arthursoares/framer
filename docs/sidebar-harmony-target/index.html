Pass 2 · Target State · 2026-04-16

A single contract for every row.

Pass 1 shipped the primitives — SidebarMetrics, SidebarControlRow, SidebarCompoundControlBlock, SidebarTrailingUnitCluster, SidebarShell. They work. What pass 1 did not deliver is harmony, because the primitives coexist with a parallel token system (SimpleLayerEditorLayout), a chassis that doesn't participate (LayerPanelRow), and per-component metric re-instantiation that lets every editor drift quietly.

This document specifies the target state after pass 2: one token namespace, one label column, one trailing cluster, one readout width, one propagation path. Every layer editor is mocked at 350pt below in its post-pass form so the visual contract is unambiguous.

05 · Before / after

The seven fixes in concrete form

Each fix below shows the current drift (left, red) and the target state (right, green) — with the exact code change and the test that will lock it in.

Fix 01 · Retire SimpleLayerEditorLayout

Fold its widths into SidebarMetrics, then delete the enum. Mechanically 30 call sites; no behavior change when values match, and the 3 that don't (compactFieldWidth = 50, valueTextWidth = 36) need explicit decisions.

Before · parallel tokens
// LayerListSection.swift:1575 private enum SimpleLayerEditorLayout { static let groupSpacing = SidebarMetrics().expandedBodyInset static let fieldWidth = 55.0 // duplicates metrics static let compactFieldWidth = 50.0 // diverges! static let suffixWidth = 24.0 // duplicates metrics static let valueTextWidth = 36.0 // diverges! static let thicknessModeWidth = 80.0 static let unitPickerWidth = 100.0 }
Two widths (50, 36) silently disagree with their metric peers. Every .simpleLayerEditorInputStyle(width:) call must pick one.
After · single namespace
// SidebarMetrics.swift — additions struct SidebarMetrics { // ...existing fields let controlReadoutWidth: CGFloat // was 36 → 55 let controlSegmentedModeWidth: CGFloat // was 80 let controlUnitPickerWidth: CGFloat // was 100 } // SimpleLayerEditorLayout — deleted // All call sites now reach for `metrics.controlValueFieldWidth` etc.
Test: SidebarMetricsTests.test_defaultMetrics_retiredTokens asserts every retired constant is expressible via a single metric.

Fix 02 · SidebarTrailingReadoutCluster primitive

Today, read-only trailing values bypass the cluster and use Text(...).frame(width: valueTextWidth = 36). That's narrower than the editable 55+24=79pt trailing block, so rows that mix readable + editable values misalign their label columns.

Before · AspectRatio offsets
// LayerListSection.swift:2202-2207 trailingValue: { Text(String(format: "%.1f", params.offsetX)) .font(AppFont.mono(10)) .foregroundStyle(Color.text3) .monospacedDigit() .frame(width: SimpleLayerEditorLayout.valueTextWidth, alignment: .trailing) // 36pt }
Label "Offset X" sits further right than label "Thickness" in the editor above (which uses editable 55+24 cluster). Visually offset by 43pt.
After · readout cluster
// New primitive: Sources/FramerApp/Sidebar/SidebarTrailingReadoutCluster.swift trailingValue: { SidebarTrailingReadoutCluster(unit: "") { Text(String(format: "%.1f", params.offsetX)) .font(AppFont.mono(10)) .foregroundStyle(Color.text3) .monospacedDigit() } }
Test: SidebarLayoutContainmentTests.test_readoutAlignsWithEditableRows asserts labels align ±0.5pt across adjacent rows.

Fix 03 · Thread metrics via @Environment

Every primitive currently takes metrics: SidebarMetrics = SidebarMetrics() as a default arg. If the shell overrides the width policy, children ignore it. Environment injection makes the shell's metrics authoritative.

Before · local defaults
// SidebarControlRow.swift:79 init( _ label: LocalizedStringKey, metrics: SidebarMetrics = SidebarMetrics(), style: SidebarControlRowStyle = .default, ... ) { self.metrics = metrics } // ExportBar.swift:19 private let metrics = SidebarMetrics() // OverlayFullWidthControlRow (LayerListSection.swift:1624) private let metrics = SidebarMetrics()
Shell's metrics.replacing(widthPolicy:) at SidebarShell.swift:14 produces a value nobody reads.
After · environment-threaded
// Sources/FramerApp/Sidebar/SidebarMetricsEnvironment.swift private struct SidebarMetricsKey: EnvironmentKey { static let defaultValue = SidebarMetrics() } extension EnvironmentValues { var sidebarMetrics: SidebarMetrics { get { self[SidebarMetricsKey.self] } set { self[SidebarMetricsKey.self] = newValue } } } // SidebarShell.body ScrollView { ... } .environment(\.sidebarMetrics, metrics) // SidebarControlRow.body @Environment(\.sidebarMetrics) private var metrics
Test: SidebarEnvironmentTests.test_shellMetricsReachDescendants renders a shell with a custom width policy and asserts children report the custom tokens.

Fix 04 · LayerPanelRow chassis joins the system

Today LayerPanelRowLayout uses raw Spacing.xs/sm/xl/md for every padding. The expanded-body leading indent (Spacing.xl + Spacing.xs = 28pt) shifts every expanded editor's label column 16pt to the right of a non-expanded editor's label column. After the pass, the chassis reads metrics from environment.

Before · raw tokens
// LayerPanelRow.swift:313-333 private enum LayerPanelRowLayout { static let headerSpacing = Spacing.sm static let disclosureSize = Spacing.xl static let expandedLeadingPadding = Spacing.xl + Spacing.xs // 28pt static let expandedTrailingPadding = Spacing.xs // ...20+ more raw tokens }
Editor rows inside .padding(.leading, 28) have their label columns pushed right of the sidebar's own label grid.
After · metric-derived
// LayerPanelRow.swift — body @Environment(\.sidebarMetrics) private var metrics // Expanded body padding .padding(.top, metrics.expandedBodyInset) .padding(.bottom, metrics.rowGap / 2) .padding(.leading, metrics.outerInset) // 12pt .padding(.trailing, metrics.outerInset / 2)
Test: LayerPanelRowLayoutTests.test_expandedBodyAlignsWithSectionGrid measures X-coordinate of an inner editor's label and asserts it equals the top-level section's label X.

Fix 05 · Extract rich-affordance primitives

TemplateTokenBar (Caption), palette editor (Dither), LUT tiles, ASCII ramp (Shader), overlay library all freelance their own grids, chip flows, and tile strips. Each deserves a named primitive that reads metrics.

Before · inline freelance
// LayerListSection.swift:3620-3688 (paletteEditor) VStack(alignment: .leading, spacing: 6) { ForEach(colors.enumerated(), id: \.offset) { _, color in HStack(spacing: 8) { ColorPickerWithHex(...) Button { ... } label: { Image(systemName: "minus.circle") } } } }
Plus hardcoded HStack(spacing: 6) in LUT tiles, HStack(spacing: 2) in ASCII ramp, FlowLayout(spacing: 4) in caption tokens — four independent spacing decisions for similar affordances.
After · named primitives
// Sources/FramerApp/Sidebar/SidebarPaletteEditor.swift SidebarPaletteEditor(colors: $colors) // Sources/FramerApp/Sidebar/SidebarPreviewStrip.swift SidebarPreviewStrip(items: luts) { lut in LUTThumbnail(lut: lut) } // Sources/FramerApp/Sidebar/SidebarChipFlow.swift SidebarChipFlow(chips: tokens) { token in SidebarChip(token.label, state: .accent) }
Test: SidebarLayoutContainmentTests expanded to cover palette/strip/flow primitives — all stay within metrics.containedPreviewMaxWidth.

Fix 06 · Promote OverlayFullWidthControlRow

Private to LayerListSection.swift:1620, used only by Overlay. But the shape ("title + full-width content") is generic — every preview/library/palette/ramp row needs it. Move it to Sources/FramerApp/Sidebar/ as SidebarFullWidthRow.

Before · private + duplicate
// LayerListSection.swift:1620 — private private struct OverlayFullWidthControlRow<Content: View>: View { private let metrics = SidebarMetrics() // local default ... VStack(... spacing: Spacing.xs / 2) { ... } .padding(.vertical, Spacing.xs / 2) }
Every other "rich content" affordance (Caption tokens, LUT library, Dither palette, ASCII ramp) reinvents this shape with slightly different spacing.
After · promoted + public
// Sources/FramerApp/Sidebar/SidebarFullWidthRow.swift struct SidebarFullWidthRow<Content: View>: View { @Environment(\.sidebarMetrics) private var metrics let title: LocalizedStringKey let content: Content var body: some View { VStack(alignment: .leading, spacing: metrics.expandedBodyInset / 2) { Text(title) .font(AppFont.controlLabel) .foregroundStyle(Color.text2) content .frame(maxWidth: metrics.containedPreviewMaxWidth, alignment: .leading) } .padding(.horizontal, metrics.outerInset) } }
Consumer count jumps from 1 (Overlay) to 5 (Overlay, Caption, LUT, Shader, Dither). Single point of truth.

Fix 07 · StyledSlider stops rendering its own suffix

StyledSlider has a suffix param that draws a unit label at frame(width: 20) — which diverges from metrics.controlUnitSuffixWidth = 24. When the same row has another unit cluster nearby, suffixes render at two widths. Remove the slider's suffix path; compose via SidebarTrailingUnitCluster.

Before · double suffix system
// StyledSlider.swift:45-50 if !suffix.isEmpty { Text(suffix) .font(AppFont.mono(9)) .foregroundStyle(Color.text3) .frame(width: 20) // != metric 24! } // Consumer — InspectorView.swift:137-143 StyledSlider( value: jpegQualityBinding, range: 60...100, step: 5, suffix: "%" // in-band suffix )
When this slider appears beside a SidebarTrailingUnitCluster, units render at 20pt vs 24pt — 4pt misalignment visible.
After · cluster-only suffixes
// StyledSlider.swift — suffix param removed struct StyledSlider: View { @Binding var value: Double let range: ClosedRange<Double> var accessibilityLabel: LocalizedStringKey? = nil var step: Double = 1 // inputWidth removed — always metric } // Consumer — compose with cluster SidebarControlRow("Quality") { StyledSlider(value: jpegQualityBinding, range: 60...100, step: 5) } trailingValue: { SidebarTrailingUnitCluster(unit: "%") { TextField("", value: jpegQualityBinding, format: .number) } }
Test: StyledSliderTests.test_sliderRendersNoInlineSuffix asserts StyledSlider's body does not contain a Text child at 20pt width.

Review-driven correctness sweep

Three parallel review agents (feature-dev bug-hunter, swift-expert idiom, Codex architecture) ran at the end of pass 3. Each turned up real findings. Material fixes:

  • PresetPreviewGrid.renderTasks dictionary keyed by fresh UUIDs — orphaned prior task handles, race between .onChange and .onAppear. Replaced with single Task? plus .onDisappear cancellation.
  • SidebarPaletteEditor.resolvedIdentities minted fresh UUIDs on every render until sync — flicker. Now pure; init populates identities at first mount.
  • Attempted generic TrailingValue: View refactor; reverted. _ConditionalContent<Row, EmptyView> type-escapes an == EmptyView check, so the divider rendered under empty conditional secondaries. Result-builder stays with a doc comment.
  • SidebarFlowLayout gained typed Cache; sizeThatFits and placeSubviews share one layout computation instead of two.
  • SidebarChipFlow constrained to Hashable, keys ForEach by \.self; insertion/removal no longer rebuilds downstream chips.
  • ExportBar.queueIndicator reduced to a single .reduce(into:) over exportQueue instead of three independent .filter passes.
  • StyledToggle accessibility value uses Text (localizable) not raw String.
  • ColorPickerWithHex.label migrated from String to LocalizedStringKey matching every other sidebar primitive; hex-field a11y composes via Text + Text not runtime interpolation.
