   desktop canvas; distinguish empty, loading, rendering failure, and original

   but never show another photo's image or metadata as the new selection.
   Give mobile an explicit Before/After control and a retry path.

   Report failed/partial photo imports. Use an importable, safe filename for

3. **Accessible interaction:** make desktop filmstrip items real buttons with
   selected state; label queue actions and allow finished failures to be

   selected state, and text-scaling room.
4. **Legibility:** measure foreground/background contrast for shared text tokens;
   brighten secondary labels while preserving the warm palette and dark surfaces.
   Capture/read before and after renders before updating any affected snapshots.
5. Add focused regressions for state transitions, failed operations, and active
   state preservation. Run Core/CLI, macOS, and iOS tests plus independent review.
   Walk through the changed UI, including empty/error states and a loaded photo.
6. Deliver a fresh focused PR stack from `develop`, which now contains the
   merged cleanup stack. Leave merges to Arthur.

## Audit evidence

- The running empty desktop canvas says to select a filmstrip photo, but hides
  the filmstrip when the library is empty and offers no visible Open Photos action.
- Desktop filmstrip thumbnails appear as images in the accessibility tree.
- Both preview views can fall through to an empty-selection message while the
  selected image/original is loading; mobile never displays the view-model error.
- Preset UI uses `try?` for throwing persistence, sometimes marking failed saves
  active. Mobile exports `.framerpreset` while its importer accepts only JSON.
- Export queue clearing omits failed jobs; several queue actions are unlabeled.
- Existing `text3` contrast is 1.67–2.25:1 across the five surfaces; `text2` drops
  below 4.5:1 on panel/control surfaces. Use the W3C normal-text contrast threshold
  as a measurable readability target, not as a claim of complete conformance.

References: [W3C contrast minimum](https://www.w3.org/TR/WCAG22/#contrast-minimum),
[Apple accessibility guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility/).
