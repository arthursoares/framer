# ADR: Retire the CPU effect-render path

- **Status:** Proposed 2026-07-09 — accepted when the maintainer merges the PR that carries it
- **Decision drivers:** maintainer ruling of 2026-07-09 ("we will always have Metal available"; CPU/GPU parity is *current mechanical reality, not eternal doctrine*) and the maintainer's 2026-07-09 request to finalize the CPU-processing deprecation begun in PR #12 (commit `20d5775`)
- **Owned by:** `framer-architecture-contract` (invariant I3); study prescribed by `framer-research-frontier` (problem 5)

## Context

Every GPU effect historically had a CPU twin, dispatched GPU-first with a CPU
fallback on `MetalEffectError`. PR #12 already made the Glitch and EdgeField
buckets GPU-only, on the recorded rationale that *a fallback render that looks
different from the GPU output is worse than failing loudly*. This ADR completes
the study for everything that remains.

Full inventory (2026-07-09, main @ `f2c9521`), classified:

| CPU code | ~Lines | Class | Fate |
|---|---|---|---|
| `ShaderRenderer` 7 CPU style renderers + `gpuOrCPU` helper | 557 | FALLBACK + REFERENCE | **Delete** |
| `ShaderASCIIRenderer.swift` (whole file) | 569 | FALLBACK + REFERENCE | **Delete** |
| `ShaderPixelSortRenderer.swift` (whole file) | 246 | FALLBACK + REFERENCE | **Delete** (see note 1) |
| `DitherRenderer` CPU: 15 GPU-covered algorithms + matrices/tables, incl. the knowingly degraded mono cmykHalftone fallback | ~1,300 | FALLBACK + REFERENCE | **Delete** |
| `DitherRenderer` CPU: Riemersma (Hilbert-curve) + shared plumbing it needs | ~280 | **CAPABILITY** — inherently serial, no GPU port exists | **Keep**, dispatched explicitly by algorithm (no longer via thrown-error fallback) |
| `TextCellBucketRenderer` / `PrintSamplingRenderer` CPU loops | ~530 | **CAPABILITY** — only renderer for legacy hidden bucket variants (`.ascii`, `.halftone`, `.dithering`) with no GPU entry | **Keep**, unchanged (already variant-dispatched, not error-fallback) |
| `LUTRenderer.applyCPU` / `applyCPUReference` | ~345 | REFERENCE (LUT oracle tests) + **BENCHMARK-BASELINE** (`framer benchmark lut`, README's published numbers) | **Keep**, unchanged — separate Metal stack, out of scope |

Note 1: the `ShaderRenderer` comment claiming spans > 24 "fall back to the CPU
sort" is stale — `PixelSortRenderer` accepts spans 1–256 on GPU and never
throws by span, so on any Metal host the CPU sorter is already unreachable.
Deleting it changes no shipped behavior on Metal hosts.

## Options considered

**A. Keep dual paths (status quo).** Cost: ~2,700 lines of redundant CPU code
whose semantics must be patched in lockstep with every shader change; CPU/GPU
divergence is the repo's single most recurring bug class (pixel-sort alone took
6 fix rounds across 3 PRs). Benefit: an executable reference for parity tests,
and Metal-less hosts still render.

**B. Retire the redundant CPU code; Metal becomes a hard requirement for
effect rendering (chosen).** Cost: the executable correctness reference
disappears — parity tests must be re-anchored to frozen golden images; hosts
without Metal can no longer render `.shader`/`.dither` effect layers (they get
a thrown `MetalEffectError` instead of a silently different image). Benefit:
the lockstep-patching tax and the divergence bug class are eliminated;
failures are loud instead of visually wrong.

The Metal-less-host cost is acceptable because: all four product targets are
macOS 14+/iOS 17+ (Metal guaranteed); the repo has no CI; and PR #12 already
crossed this line for the bucket effects without incident.

## Decision

1. `ShaderRenderer.apply` calls the GPU renderers directly; `gpuOrCPU` and all
   CPU style implementations are deleted. `MetalEffectError` propagates.
2. `DitherRenderer.apply` dispatches **by algorithm**: `.riemersma` → the kept
   CPU implementation (sole implementation, not a fallback); everything else →
   `DitherGPURenderer`, errors propagating. The degraded mono cmykHalftone CPU
   fallback is deleted.
3. The legacy hidden bucket variants and the entire LUT stack are unchanged.
4. **Verification strategy replacing CPU-vs-GPU parity:** each retired
   reference becomes a frozen golden PNG committed under
   `Tests/FramerCoreTests/Resources/GoldenReferences/`, generated by an
   env-gated test (`FRAMER_REGENERATE_GOLDENS=1`) whose command is recorded in
   the test file. Tests assert GPU output vs golden within the same per-effect
   mean/max byte-delta tolerances the parity tests used (predicted same-machine
   delta: mean 0.0 / max 0; the inherited tolerances are cross-machine
   headroom). GPU-only invariant tests (binary-BW, palette-only, dimensions)
   are unchanged. Golden refresh follows the snapshot-hash discipline: never
   blind-refresh; land the refresh in the same commit as its cause, with the
   pixel-level explanation.

## Consequences

- House rule 5 ("shader changes patch CPU and GPU in the same commit") is
  superseded by: *shader changes must keep the golden-reference tests green;
  a deliberate look change regenerates goldens in the same commit with an
  explanation of the pixel shift.*
- `EffectGPUParityTests` is renamed to reflect its new anchor; the two
  fallback-routing tests change meaning: Riemersma routing is now asserted as
  explicit dispatch; the cmykHalftone Metal-less fallback test is deleted with
  the behavior.
- Skills/docs updated in the same PR: `framer-architecture-contract` I3,
  `framer-change-control` rule 5, `framer-validation-and-qa` test estate,
  `framer-research-frontier` problem 5 (resolved by this ADR), CLAUDE.md house
  rule 4, and the stale GPU-fallback comments in `FrameProcessor.swift` /
  `GPUEffectsPlatform.swift` left over from PR #12.
- Future work items this unblocks or reshapes: per-effect verification for the
  12 bucket effects (research-frontier problem 1) anchors to goldens from day
  one instead of writing CPU twins.
