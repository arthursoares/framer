desktop sidebar only · implementation-synced comparison

Sidebar harmony for the macOS inspector.

This brief compares the three sidebar-only directions against the shipped canvas + inspector desktop shell. It stays grounded in the implemented sidebar system — PRESETS, LAYERS, OUTPUT, EXPORT QUEUE, Modified, Selected, All, and the shared SidebarShell, section, row, and state primitives that now define the inspector.

Recommended above the fold · Balanced

Choose Balanced as the shipped direction.

Balanced is the implemented sidebar system: a bounded 304 / 320 / 352 width policy, one SidebarShell, shared section rhythm, shared row and control primitives, and aligned support surfaces such as PresetPreviewGrid, PresetPreviewCard, and ExportBar. It is more coherent than Conservative and materially less risky than Bold.

Summary

Executive summary

  • Conservative reduces risk but leaves too much current drift intact.
  • Balanced unifies shell, row grammar, and state language without changing user outcomes.
  • Bold creates the strongest point of view, but asks the implementation to absorb more visual and structural churn than this phase needs.
Design principles

Principles

The comparison uses the same decision criteria throughout so the recommendation is traceable instead of stylistic. The target mood stays aligned with the project’s Darkroom Editorial brief: dark surfaces, warm analog accents, precise data typography, and a sidebar that reads as one instrument panel.

01

Clarity first

Keep PRESETS, LAYERS, OUTPUT, and the pinned ExportBar legible at a glance, especially once dense editors expand.

02

One shell contract

Treat the inspector as a single SidebarShell rather than a stack of unrelated panels with slightly different padding, borders, and row behaviors.

03

State consistency

Hover, expanded, selected/current, disabled, dragging, drop target, and focus should read as one family across preset cards, layer rows, controls, and export surfaces.

04

Measured ambition

This phase is sidebar-only. The winning option should avoid drifting into top bar, canvas, filmstrip, or iOS redesign territory.

Element-by-element analysis

What changes where

This section stays anchored to the current desktop code map and the sidebar primitives now present in the app. It focuses only on the inspector stack and its related sidebar surfaces.

Shell

SidebarShell

`InspectorView` now renders through `SidebarShell`, and `SidebarLayoutPolicy` defines the approved 304 / 320 / 352 width band. Balanced turned the inspector into one bounded adaptive panel with explicit outer inset, row spacing, and footer anchoring instead of a fixed-width column with local exceptions.

Takeaway: make the shell explicit, not accidental.

Sections

PRESETS, LAYERS, OUTPUT

Conservative leaves section cadence mostly untouched. Balanced gives all three sections the same header rhythm, spacing, and body framing, while still preserving current product language. Bold would separate them more aggressively and introduce heavier visual chapter breaks.

Takeaway: shared section cadence is low drama, high value.

Preset surfaces

ActivePresetBanner + PresetPreviewGrid

The `Modified` state, preset apply/update actions, and visual card language are now aligned through `PresetPreviewGrid`, `PresetPreviewCard`, and `SidebarStateStyle`. Balanced keeps presets leading the sidebar while making their banner, cards, and support actions feel like part of the same state family as the rest of the inspector.

Takeaway: presets should lead the sidebar, not visually detach from it.

Row grammar

Layer rows and control rows

Layer rows, `FormatPicker`, `StyledSlider`, `StyledToggle`, and the simpler control views now share the same grammar through `LayerPanelRow`, `SidebarControlRow`, and `SidebarCompoundControlBlock`. Balanced is the option that made one row chassis real: one label/value rhythm, one disclosure rhythm, one badge language, and one family of hover, expanded, focus, dragging, and drop-target states.

Takeaway: row consistency is the real heart of sidebar harmony.

Dense editors

Canvas, Overlay, Caption, Dither, LUT, Shader, GPU Effect

Dense editors are where a purely conservative pass starts to break down. Balanced gives them a stronger compound-control block structure without pretending they need the same density as a simple toggle row. Bold risks styling density so strongly that it becomes visually louder than the user’s actual photo work.

Takeaway: dense blocks need structure, not spectacle.

Footer actions

ExportBar and queue states

Balanced preserves the existing `Selected`, `All`, and `EXPORT QUEUE` vocabulary, and `ExportBar` now reads as part of the same sidebar system: clearer button hierarchy, shared spacing, and queue states that belong to the same state matrix instead of a detached status strip.

Takeaway: the footer should close the panel with confidence.

Recommendation

Recommendation

Balanced remains the right recommendation because the shipped result improved the experience in visible ways, delivered the shared sidebar narrative the brief argued for, and still respected the sidebar-only scope boundary.

Recommended direction

Balanced

Balanced now defines the shipped sidebar system: one SidebarShell, one section contract, one row grammar, and one state language shared across preset cards, layer rows, dense editors, and ExportBar.

Why this wins overall

Clarity without drift

  • It keeps current labels and user outcomes intact.
  • It turned the brief into a concrete shipped sidebar system.
  • It improves coherence more meaningfully than Conservative.
  • It avoids the implementation appetite required by Bold.
Borrowed ideas / trade-offs

What to borrow, what to avoid

The recommendation still benefits from elements of the other two directions. This keeps the winning option from reading like a total rejection of the alternatives.

Borrow from Conservative

Restraint

  • Keep button copy and current labels unchanged where they already work.
  • Preserve the current mental model of sections and pinned footer placement.
  • Favor subtle cleanup over decorative chrome when the photo workflow would not benefit.
Borrow from Bold

Confidence

  • Use stronger hierarchy between shell, section headers, and active states.
  • Let warm analog accents do more than merely highlight active buttons.
  • Give the sidebar a memorable editorial point of view, but only within the approved desktop scope.
Trade-off to accept

Balanced is not the cheapest pass

It asks the implementation to define shared sidebar primitives instead of simply polishing local views. That is intentional: the extra effort buys consistency and makes later migration work much more defensible.

Trade-off to avoid

Do not oversell this document

This page is a comparison brief, not a claim that every future sidebar refinement is settled forever. It should stay honest about what shipped: Balanced is the implemented direction, while Conservative and Bold remain useful reference points for restraint and future exploration.
