# v3.0.0 — Safer exports and recoverable presets

This release includes all six reviewed PRs merged after the v2.2.1 build:
#54, #50, #53, #52, #51, and #55, plus the Custom crop and keyboard-navigation
improvements from that build.

## Why a major version

The public FramerCore API `UserPaletteStore.list()` now throws read/decode
errors instead of returning an empty collection for unreadable data. Swift
clients must use `try` and handle failures. This source-breaking change is the
reason for version 3.0.0. Native app and CLI users receive the saved-data and
export fixes described below.

## Safer exports

- Explicit CLI config/preset load failures and invalid styles, colors, dimensions,
  quality, and aspect-ratio overrides now produce actionable validation errors.
  Automatic config discovery retains its existing fallback behavior.
- Single-file CLI exports reject the input photo as their destination, including
  normalized-path, symbolic-link, and hard-link aliases.
- Desktop exports choose unique filenames before rendering. Existing filenames,
  case-insensitive collisions, and names reserved by other running jobs are
  avoided; reservations remain held until cancelled work finishes.

## Recoverable saved data

- Failed reads or decoding of saved palettes stop save/delete operations before
  replacement. macOS and iOS show an error while preserving the original file.
- Unsupported JSON/YAML layers and unknown YAML shader/effect kinds fail loading
  rather than silently dropping layers or switching to a different render path.
  Unreadable preset files remain intact for recovery.
- Historical source-build dither presets missing preprocessing fields load with
  the complete stack preserved and the established defaults: threshold 0.5,
  sharpen 0, and contrast 0. Malformed present values still fail validation.

## Editing improvements from the v2.2.1 build

- Custom aspect-ratio Width and Height controls are editable on macOS and iOS.
  The choice survives layer collapse, Undo, and preset save/load.
- macOS filmstrip arrow navigation keeps photo selection and keyboard focus
  synchronized, including after menu navigation, and stops at library boundaries.
- GitHub Pages showcases the native editors, current photo finishes, and
  downloadable effect recipes with updated installation examples.

## Consistent controls and validation

- macOS and iOS share the common, geometry, and color parameter mutations for
  all four GPU-effect families. Layer identity, enabled state, effect payloads,
  opacity, blend mode, and unrelated parameter groups are preserved.
- CI now compiles both native apps and runs focused macOS and iOS interaction
  tests alongside the existing Core/CLI checks.

## Installation and compatibility

Download `framer-v3.0.0-macos-arm64.tar.gz` and `SHA256SUMS`, then run:

```bash
shasum -a 256 -c SHA256SUMS
tar -xzf framer-v3.0.0-macos-arm64.tar.gz
./framer --version
```

Keep `framer` and `framer_FramerCore.bundle` together. The archive is an unsigned
Apple Silicon CLI requiring macOS 14 or later. Native apps remain available
from source; this archive is not a signed/notarized macOS app or an iOS installer.
The iOS deployment target remains iOS 17 or later. Overlay textures remain
separate source/LFS assets.

FramerCore consumers must now handle errors from `UserPaletteStore.list()`;
save/delete already throw and now propagate read/decode failures as well.

The new CLI source-alias guard applies to single-file processing. For CLI batch
processing, use a separate output directory: writing into the input directory
can still overwrite another source photo. Desktop filename reservations
coordinate jobs within one app instance; external writers are not locked out.
