## Pass 2 (2026-04-16) — one contract across every row

- The pass-1 primitives worked but lived alongside a parallel token namespace (`SimpleLayerEditorLayout`), a chassis that ignored them (`LayerPanelRow`), and per-component `SidebarMetrics()` re-instantiation; pass 2 deleted the parallel namespace, threaded metrics through `@Environment(\.sidebarMetrics)`, and migrated the chassis + five editors to the shared contract. Outcome: 9 primitives cover every shape, 30+ call sites reference one namespace, shell overrides reach descendants instead of falling on the floor.
- `SidebarTrailingReadoutCluster` intentionally mirrors `SidebarTrailingUnitCluster` widths (`controlReadoutWidth = controlValueFieldWidth = 55`). Adjacent editable/read-only rows now share a trailing block width so label columns align without per-editor manual tuning. Lock the invariant with a pure equality test — `editableBlockWidth == readoutBlockWidth` — before introducing any new read-only rows.
- Environment threading in SwiftUI is invisible unless the primitive exposes an explicit override. Use the pattern: `@Environment(\.sidebarMetrics) private var envMetrics`, `private let overrideMetrics: SidebarMetrics?`, `private var metrics: SidebarMetrics { overrideMetrics ?? envMetrics }`, and keep the initializer’s `metrics:` param optional (`SidebarMetrics? = nil`). That preserves the ability to pass custom metrics in previews/tests without forcing every default consumer to go through the old path.
- `LayerPanelRow`’s expanded body leading padding is the single lever that aligns inner editor label columns with the section grid. Replacing `Spacing.xl + Spacing.xs` with `metrics.outerInset` cuts 8pt of drift and makes the editor-row label column identical to the section-header outer inset. Trailing inset halves to `metrics.outerInset / 2` for symmetry — close enough to the prior `Spacing.xs` that snapshots don’t shift, but derived from metrics so a future inset change propagates.
- Rich-affordance primitives (`SidebarFullWidthRow`, `SidebarPreviewStrip`, `SidebarPaletteEditor`, `SidebarChipFlow` + `SidebarFlowLayout`) each own their containment boundary (`metrics.containedPreviewMaxWidth`) so overlay libraries, LUT tile strips, caption token flows, and dither palettes never need per-call-site width math. `SidebarPreviewStrip` grew optional `tileWidth`/`tileHeight` to accept tall tiles (LUT thumb + text label) without special-casing.
- `StyledSlider`’s `suffix:` path rendered at 20pt, diverging from `metrics.controlUnitSuffixWidth = 24`. Removing the suffix branch (and the `inputWidth` parameter) and composing via `StyledSliderWithUnit` — which uses the canonical 24pt unit column — fixes the 4pt misalignment visible when a slider neighboured a `SidebarTrailingUnitCluster`. Callers migrate by renaming `suffix:` → `unit:` on `DenseSliderControlRow`, or by swapping `StyledSlider` → `StyledSliderWithUnit` for direct call sites (overlay opacity, inspector jpeg quality).
- Snapshot hash churn during the pass: each of Tasks 1–7 shifted at most 1–4 hashes. Keep commits small — one task per commit with its hash refresh inline — so a later bisect can attribute a visual regression to a single step. Tasks 1 / 3 / 4 / dither-palette / ASCII ramp did NOT shift snapshots because those surfaces weren’t rendered in the canonical nine; explicit containment/environment tests protected the behaviour anyway.

## Pass 3 (2026-04-16) — smoke-test bugs, Codex review, and correctness sweep

### Smoke-test-driven fixes (visible user-facing bugs)

- **Color picker label chip.** `ColorPickerWithHex` renders SwiftUI's native `ColorPicker(label, selection:)` which draws the label inline next to the well. Any non-empty label produced a stray "Color" / "Fill Color" / "Foreground" text chip floating mid-row. Applied `.labelsHidden()` to the inner picker + accessibility label, and introduced a private `labeledColorPicker(_:selection:onHexCommit:)` helper in `LayerListSection` that wraps the leaf in `denseControlRow(title)` so the visible label now lives in the sidebar's 104pt label column. Renamed 23 call sites (GPU variants, Caption font color, Dither FG/BG, Shader colors, Padding Fill Color) via perl. Two `ColorPickerWithHex("")` call sites remain — Border and `SidebarPaletteEditor` — both intentionally empty-labelled and already wrapped in proper row primitives.
- **Min-width segmented picker overflow.** At 300pt min sidebar, multi-option segmented pickers with long labels exceeded the 162pt content budget. Orientation Target (Portrait / Landscape / Square) and Overlay Category (Frames / Dust / Light Leaks / Wet Plate) converted to `.menu` pickers. Short-labelled / fixed-width segmented pickers (Border px/%, Canvas cm/mm, Pixels/Physical) stayed segmented — they fit the budget and the bounded state-selection affordance remains useful at a glance.
- **Slider vs. trailing-field overlap.** macOS NSSlider (backing SwiftUI's `Slider`) rasterises its track/knob to the very edge of the layout frame — sometimes slightly past it via AppKit's layer-level drawing path. Combined with the 10pt HStack gap this was visibly touching the trailing field's rounded rectangle. Fix in `SidebarControlRow.body`: `.clipShape(Rectangle())` hard-clips any AppKit overflow, and the trailing pad was bumped to `controlColumnSpacing` (10pt) giving a 20pt total gap between content and trailing when `trailingValue.hasContent`. The clip is the structural fix; the pad is the belt + suspenders.
- **`DenseSliderControlRow` layout contract drift.** When a `unit:` was passed, the row used `StyledUnitSlider` which stuffed `slider + field + unit` all into `SidebarControlRow`'s content slot — off-contract. Refactored to split: `Slider` in content, `SidebarTrailingUnitCluster { TextField }` in the trailingValue slot, both driven by a shared `snappedBinding` via `StyledSliderValueResolver.constrain`. Also fixed two inline callers that duplicated the off-contract pattern (Overlay opacity, Inspector Quality row).
- **Collapsible Presets section.** New `CollapsibleSidebarSection` primitive with a chevron in the header. When collapsed and an active preset exists, the collapsed state shows the active-preset summary banner (name + Modified badge + dismiss button) in place of the grid. Persistence via `@AppStorage("sidebarPresetsSectionExpanded")`. Thumbnails had to move off of `@State` into `AppState.presetThumbnailCache` because SwiftUI tears down the grid's state when the section collapses — otherwise every expand cycle would re-render from scratch.
- **Caption None mode.** Removed from the Mode picker (only Template / Custom). The layer visibility toggle is the correct way to disable a layer; `.none` mode duplicated that affordance. Legacy layers auto-migrate to `.template` via `.onAppear`. The `.none` enum case stays in `CaptionMode` for preset-YAML back-compat.
- **Dither Custom palette selection silent no-op.** When the user picked "Custom" from the preset dropdown, the setter seeded with `VintagePalette.gameBoy` — which `VintagePalette.Preset.matching(colors)` then recognized as `.gameBoy`, snapping the picker back. Fix: append a neutral `#808080` swatch so the palette shape doesn't match any canonical preset (and `matching()` returns `.custom` on the next render). Plus a guard: if user picks the already-selected preset, bail early. Also: trim base to `MAX_PALETTE_COLORS - 1` before appending so the neutral isn't silently dropped at max-palette edges.

### Pixel Sort GPU wiring (user-requested feature from audit)

- Pass-2 audit found `GPUEffectKind.pixelSort` was hidden from `userFacingCases` because `GlitchGPURenderer` only implemented VHS — pixelSort's GPU path didn't exist. Pass 3 re-exposed it: `GlitchGPURenderer.renderPixelSort` bridges `GlitchParameters` to the existing `pixelSortFragment` in `PixelSort.metal` (same shader the `.shader` layer's PixelSort style uses). The bucket variant doesn't expose Kim-Asendorf span modes — `spanMode` hardcoded to 0 (classic luminance span), `streakLength` maps to `spanCap` via a quadratic curve `max(1, Int(streakLength² × 255 + 1))` which gives fine control in the 0..0.5 band. `.ascii`, `.halftone`, `.dithering` stay hidden (canonical paths live in `.shader` layer or Dither layer).
- **CPU/GPU pixel-sort parity bug.** `GlitchRenderer.pixelScore` had TWO divergences from the GPU shader: `.brightness` returned Rec.709 luminance (identical to `.luminance`) instead of `max(r,g,b)`, and `.hue` returned unnormalised HSV sectors in `[-1, 6)` — negative scores always fell below any positive threshold on CPU, leaving blue-dominant pixels unsorted. Fixed both to match `psSortValue` in `PixelSort.metal`: brightness = maxRGB, hue = HSV / 6 with negative-wrap.

### Review-driven correctness sweep

- **`renderTasks[UUID()] = task` leak.** The preset thumbnail renderer kept a dictionary keyed by fresh UUIDs — each call overwrote the key of the previous task, so cancellation iterated an already-rotated map and the original task was orphaned. If `.onChange(of: renderKey)` and `.onAppear` both fired (which they do on first appear + any subsequent photo change), the first batch could continue running and write stale previews into `appState.presetThumbnails` on MainActor from the background context. Replaced with a single `@State var renderTask: Task<Void, Never>?` — cancel-before-replace guarantees at most one in-flight batch. Added `.onDisappear` cancellation for good measure.
- **`SidebarPaletteEditor` identity flicker.** `resolvedIdentities` generated fresh UUIDs on every render pass until `.onChange(of: colors.count)` fired, so new rows flashed through multiple IDs and ColorPicker instances rebuilt. Fix: pure accessor that truncates to `colors.count` but never mints. Populate identities in a dedicated `init` (from `colors.wrappedValue.map { _ in UUID() }`) so the first render already has matching IDs and there's no empty-palette flash on mount.
- **`CollapsibleSidebarSection` content peek during collapse.** Without clipping, the `.move(edge: .top)` transition briefly peeked above the header before opacity reached zero. Wrapped the conditional content in a clipped VStack. Also switched the animation driver from `withAnimation` inside the button tap to `.animation(_:value:)` on the outer VStack — modern SwiftUI transaction propagation.
- **Deleted-preset thumbnail cache leak.** The delete context-menu action removed the preset from storage but left its thumbnail in the cache until the next renderKey change fired. Synchronous purge via `appState.presetThumbnailCache.remove(presetID:)` before `loadPresets()`.

### Architecture

- **Three slider wrappers collapsed to two.** `StyledSlider` (bare, no unit) + `StyledUnitSlider` (inline convenience, kept only for tests + future callers) + `DenseSliderControlRow` (the canonical row shape). Production code only uses the first and third now. The `StyledUnitSlider` tests guard against accidental reintroduction of `StyledSlider`'s inline suffix path via bitmap SHA diff.
- **Result-builders earn their keep.** The swift-expert reviewer flagged `SidebarControlRowTrailingValueContent` and `SidebarCompoundControlBlockSecondaryContent` as "solving a non-problem" and suggested replacing with generic `TrailingValue: View`. Attempted the refactor, watched a snapshot fail — `secondary: { if flag { row } }` resolves to `_ConditionalContent<Row, EmptyView>` which a type-based `== EmptyView` check misses, so the divider rendered under a conditionally-empty secondary. Reverted, documented WHY the result-builder stays in both primitives. The runtime `.absent` case is the only way to distinguish "no trailing closure" from "trailing closure's current branch is empty".
- **`PresetThumbnailCache` extracted.** Thumbnails used to live directly on `@Observable AppState` — every write during the concurrent render batch invalidated every view tracking any AppState property. Moved to a dedicated `@Observable @MainActor final class PresetThumbnailCache` with `private(set)` backing and `store/remove/resetKey/thumbnail(for:)` API. Observation scope now matches what views actually read.
- **`SidebarFlowLayout.Cache` implemented.** `sizeThatFits` and `placeSubviews` were computing layout twice per pass. Typed `Cache` struct keyed by `(maxWidth, subviewCount)` gives single computation per layout, meaningful for Caption token bars with 12+ chips.
- **`SidebarChipFlow` requires `Hashable`.** Using `\.offset` as ForEach ID meant every insertion or removal rebuilt every downstream chip. Requiring `Hashable` on `Data.Element` and keying with `\.self` makes SwiftUI only rebuild the actually-changed rows. `TemplateToken` gained auto-synthesized Hashable.

### Snapshot tests

- Pass-3 total snapshot hash churn: ~12 hashes updated across 10 commits. Every update intentional and attributable to one commit. The SHA-based approach is fragile on cross-machine (font rasterisation, GPU compositing) but locally it's been catching EVERY layout drift — including ones the author didn't expect. Worth keeping.
- When a primitive refactor is supposed to be semantically transparent but snapshots shift: most often it's the hidden case where the old primitive's internal state (like `hasContent`) diverged from what a naive type-based check returns. Snapshot diff is the forcing function; read the pixels, not the diff.
